# ADR-001: Delivery team and runtime automation are separate bounded systems

**Status:** PROPOSED — requires human architecture approval before implementation.
**Date:** 2026-10-31
**Decision owner:** Human sponsor; FDU Outcome Lead authors design; Engineering Architect and Security review.

## Decision
Reuse the existing 15 OpenClaw delivery agents, with the Outcome Lead and Pod Lead as communication-only coordinators. Sandbox specialist tool execution and prohibit ungated production operations. Build the equipment-fulfillment MVP with a bounded planner and deterministic policy/transaction controller rather than a runtime multi-agent swarm.

## Options assessed
- **15-agent operational swarm:** maximum specialization, but high privilege/coordination blast radius and inadequate deterministic order/approval guarantees. Reject for MVP.
- **One bounded planning component + deterministic policy/execution control:** lower coordination cost, testable risk gates, inspectable operational evidence. Select for MVP.
- **Fully deterministic rules with no LLM:** lowest autonomy risk, useful baseline/fallback; assess whether a planning assistant adds value before shipping.

## Constraints
Real tool fulfillment can trigger equipment availability, customer commitments, cross-border compliance, inventory, manufacturing, and safety outcomes. Each system remains authoritative for its own state, and no LLM may authorize or silently override a failed predicate. External write adapters must be introduced only after system owner, compliance, architecture and release approval.

## Tradeoffs
A single planner may miss context a domain specialist would catch; mitigate with domain-owned rules, structured source references and human acceptance. Deterministic rule coverage requires domain-maintained policy and regression tests. Sandbox denies network, so GitHub publication will require a separately approved broker/publisher.

## Revisit trigger
Consider a separate runtime specialist agent only when instrumentation shows the single planner cannot meet verified tasks without unacceptable error/latency AND a separately isolated specialist can materially improve quality under the same review controls. Avoid additional swarm layers unless evidence justifies them.
